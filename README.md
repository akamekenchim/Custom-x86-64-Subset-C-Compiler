# 🎓 Educational x86-64 C Compiler in C

A lightweight, educational C compiler toolchain written from scratch in C. This project compiles an imperative subset of C directly into clean, unoptimized Intel-syntax x86-64 Assembly (`.asm`), designed specifically for **visualizing code lowering, stack memory layouts, and assembly generation**.

Unlike industrial compilers like GCC or Clang—whose generated assembly is often obfuscated by aggressive optimizations and complex assembler directives—this compiler generates **transparent, 1:1 mapped x86-64 assembly** compliant with the **Windows x64 ABI**.

---

## 🎯 Educational Purpose: Why Use This Compiler?

Standard production compilers hide low-level mechanics behind heavy frameworks and optimizations. This project was built to remove the "magic" and serve as a transparent pedagogical tool for understanding:

1. **Clean Code Lowering:** Observe exactly how high-level C constructs (`if-else`, `while`, `for`, `break`, `continue`) map directly to basic blocks, conditional jumps (`je`, `jne`, `jl`), and label stacks.
2. **Memory Layout & Pointer Mechanics:** See explicit scale-factor arithmetic ($sizeof(T)$) during pointer math, array indexing stack offsets, and stack frame allocation.
3. **Type Promotion & Byte Operations:** Explicitly track how `char` (1 byte) vs. `int` (4 bytes) operations generate sign/zero-extension instructions (`movsx`/`movzx`) and byte-register access (`AL`, `CL`).
4. **ABI Realities:** Inspect standard x86-64 calling conventions, including 32-byte shadow space allocation, `RBP` frame management, and 16-byte stack alignment.

## 🏛 Architecture & Pipeline

```
[ C Source Code (.c) ]
         │
         ▼
[ Lexical Analyzer ] ───> Lexical Tokens
         │
         ▼
[ Cascading Parser ] ───> Abstract Syntax Tree (AST)
         │
         ▼
[ Semantic Analyzer ] ──> Symbol Table & Type Validation
         │                (Type propagation, pointer/array scaling, 
         │                 scope resolution, break/continue validation)
         ▼
[ Assembly Generator ] ──> Readable Intel Assembly (.asm)
         │                (RBP stack frames, ABI shadow space, 
         │                 movsx/movzx byte handling, loop label stacks)
         ▼
[ GCC Assembler/Linker ] ─> Executable Binary (.exe)
```

## 🔍 Code Transformation Showcase

Here is a side-by-side comparison of how high-level C code lowers into transparent x86-64 assembly generated by this compiler:

### **Input C Code (`test.c`)**
```c
int arr[2];
int* ptr = arr;
*ptr = 42;
```

### **Generated x86-64 Assembly (`target.asm`)**
```assembly
# Allocation & Setup: arr at [rbp-8], ptr at [rbp-16]
# 1. Compute address of arr and store in ptr
lea rax, [rbp-8]
mov qword ptr [rbp-16], rax

# 2. Dereference ptr (*ptr = 42)
mov rax, qword ptr [rbp-16]   # Load address stored in ptr
mov dword ptr [rax], 42       # Write 4-byte integer 42 to address
```

## ✨ Key Technical Highlights

### 1. Front-End Parsing & Grammar
* **Hand-Written Parser (Zero External Tools):** Built using a cascading recursive descent approach without reliance on Flex, Bison, or Yacc.
* **Expanded Type Support:** `int` (4-byte scalars), `char` (1-byte scalars), multi-level pointers (`int*`, `char*`), and fixed 1D arrays (`int arr[10]`).
* **Nested Control Flow:** Support for `if-else`, `while`, and `for` loops with arbitrary nesting depth.

### 2. Semantic Analysis & Type System
* **Pointer Arithmetic & Array Decay:** Automatically handles scaling ($sizeof(T)$) during pointer operations (`ptr + 1` moves 4 bytes for `int*` vs. 1 byte for `char*`).
* **Loop Context Stack:** Employs a label-tracking stack during AST traversal to correctly route `break` and `continue` statements to their nearest enclosing loop block.
* **Semantic Error Trapping:** Detects symbol redeclarations, undeclared identifier references, and type mismatch violations.

### 3. Low-Level x86-64 Code Generation
* **Intel Syntax Compliance:** Outputs standard `.intel_syntax noprefix` format.
* **Windows x64 ABI Alignment:** Correctly formats 32-byte shadow space allocation, frame pointer (`RBP`) tracking, stack layout alignment (16-byte boundary), and System V / Windows `printf` invocations.
* **Byte-Level Memory Operations:** Emits `movsx` / `movzx` instructions for `char`-to-`int` widening and byte-register access (`AL`, `CL`, `BYTE PTR`).

## 🚀 Building & Running

### Requirements
* **Windows GCC Toolchain** (e.g., MinGW-w64)
* **Make Utility** (`mingw32-make`)

### Step-by-Step Execution

#### 1. Build the Compiler
Clone the repository and build the binary via `Makefile`:
```bash
mingw32-make
```
*This produces the compiler executable `NttTrang.exe` along with intermediate object files.*

#### 2. Compile C Source Code to Assembly
Run the compiler against a target C source/test file (e.g., `test.txt`):
```bash
./NttTrang test.txt
```
*The compiler parses `test.txt` and generates readable x86-64 assembly in `target.asm`.*

#### 3. Assemble, Link, and Run
Assemble `target.asm` using GCC and execute the resulting binary:
```powershell
gcc -x assembler -masm=intel target.asm -o target.exe ; if ($?) { .\target.exe }
```
